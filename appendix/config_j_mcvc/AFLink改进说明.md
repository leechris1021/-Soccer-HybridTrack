## §0 结论先行

改进版 AFLink 只做了三件事：

1. **放宽名义窗口** `150/450 → 250/450`（长中断不再被 gap 硬剪掉）。
2. **加一道队色等价类否决（核心）**：删掉「跨队/跨侧」与「离群碎片 vs 队内」的候选，**只删不增、零参数、零训练**。
3. **让自适应门控退役**：门控（自适应 / 锥形 / 残差 / 运动学）不参与评分与筛选，仅作可选剪枝保留。

设计原则（源码注释 `:94-132` 原文）：

> **否决型增益的上限由「否决的精确率」决定，而不是由可用信息量决定。**

证据：队色否决否决率 56~59% → 涨点；方向否决率 57.4%（几乎相同）→ 掉点（§10）。形态同为离散否决，差别只在精确率。

### 阶梯表（务必区分「是否开队色否决」）

| 配置 | 队色否决 | train | test | 出处 |
|---|---|---|---|---|
| `(150,450)` 名义窗口 | 开 | 64.517 | 64.143 | `_sens250/sens250.md` 表9 基准行 |
| **`(250,450)` + 队色否决 = 最终（入选）** | 开 | **64.872** | **64.306** | 表9 `**` 行 |

| 全量级联（T1+T2+V3a+V3b+T4，5 层） | 开 | 64.638 | 64.188 | 同上（**更差**） |

> `(250,450)` 无否决（63.745/63.005）**低于** `(150,450)` 带否决（64.517/64.143）：窗口放宽本身不是增益来源，**「宽窗 + 精确否决」才是一组**。

## §4 队色等价类否决（核心，V2）

### 4.1 判据（刻意不对称）

`_should_veto_kit()` `:807-825`：

```text
off  不否决（默认，本功能不存在）
side 跨侧否决：kit_side_of(a) != kit_side_of(b)
any  两侧标签都已知且不同 → 否决        ← 最终方案
all  全否（破坏性自检：HOTA 必须崩，否则说明钩子没接上）
```

核心两行（`:821-825`）：

```python
if label_a is None or label_b is None:
    return False           # 标签未知一律放行
return label_a != label_b  # 'c0' vs 'c1'、'cX' vs 'c0'/'c1' 都命中
```

**不对称的理由**：「宁可漏否决，不可误否决真候选」。这正是 V3b 层想补的漏洞（§8），但实测从不触发。

### 4.2 标签口径

`load_kit_labels()` `:148` 读 `{seq: {track_id: label}}`：

- **像素版（可上线）**：`c0` / `c1` / `cX`（`cX` = 离群碎片：裁判/球/异色门将/取色失败/非高置信，常量 `:92`），由 `_probe_color_team.py --stage pixels --dump-labels <PATH>` 生成。
- **oracle（仅测上界，不可上线）**：`left` / `right` / `left_gk` / `right_gk` / `ref` / `ball`，配 `kit_veto='side'`。

`kit_side_of()` `:135` 有个反直觉结论：`side` 模式下 `None` 不代表「无法判断」，而代表「不属于任何一侧」，故**「裁判/球 vs 球员」会被判跨侧而否决——实测这部分收益比跨侧召回本身还大**。

### 4.3 实现与统计

`_apply_kit_veto()` `:827-843` 在候选出口做线性筛选，累计逐序列 `kit_veto_stats` 与全局 `kit_veto_totals` 的 `candidates` / `vetoed`，用于核对否决率。标签表取用 `_kit_table()` `:797`：优先序列名，退回 `id(track_map)`。

### 4.4 为什么叫「等价类」

把队色当**等价关系**而非单属性，链接就必须保持等价类。V2 的不对称会留下 `s(A) → d(未知) → e(B)` 这类跨类路径，路径上至少一条边是假链接。V3b 想用「按得分递减加边的并查集，删掉第一条把两个队色连通起来的边」切断它（`:126-130`，声称是可证明的必要条件、零参数零训练）——**实测从不触发，判为死层**。保留这段形式化依据是为记录设计动机。

## §5 门控层：为什么退役

### 5.1 曾经的形态

`adaptive_gate` / `adaptive_tri` / `adaptive_cone` / `kinematic_gate`（`:1621-1624`）为每条候选算**动态** gap/dist 上限，再按「可靠性 × 形状」在 `[min_ratio, max_ratio]` 间缩放窗口；锥形则是 `dist_limit = v_max·gap`（所有轨迹共用一条直线）。

### 5.2 退场理由

1. **增益不显著**：门控在位（Config I 口径）train 63.781 / test 63.049，退场后的 MCVC 骨干 64.872 / 64.306。
2. **叠加边际符号翻转**：在队色否决之上再叠锥形 test `−0.0721` / train `+0.0450`；锥形单开 test `+0.2157`（CI `[+0.0322, +0.4512]`）但 train `+0.1109`（CI `[−0.0273, +0.2498]`，Wilcoxon `p=0.05429`）→ **两个划分各站一边**（`:115`）。
3. **与窗口族结构重合**：锥形只是全局速度上限，任何固定窗口都能近似复现其筛选集合。

结论：门控**不参与评分标定**（`gate_score_norm=nominal`，`:2067`），窗口固定名义 `250/450`，锥形仅作可选剪枝 `--mcv_cone`（`:2020`）。

### 5.3 归一化解耦（`gate_score_norm`）

`effective`（默认）= 按门控缩放后的**有效窗口**归一化；`nominal` = 一律按**名义窗口**归一化。最终固定 `nominal`：把「窗口放宽」与「归一化尺度」拆开，否则一放宽窗口，所有时间项/距离项分数被整体压缩，贪心排序跟着变，涨点掉点分不清归谁。

## §6 打分层

`compute_rule_score()` `:1856-1882`：

| 分支 | 公式 | 触发 |
|---|---|---|
| **baseline（最终）** | `0.5·temporal + 0.5·distance`（`:1881`） | `baseline`（以及门控/锥形/残差/运动学变体） |
| 三因子 | `tw·temporal + dw·distance + sw·shape`（`:1875-1877`） | 仅 `tri_factor` / `adaptive_tri`（`:1652-1653`） |
| 长度置信 | `0.4·temporal + 0.4·distance + 0.2·length_conf`（`:1878-1879`） | 仅 `length_conf` / `gap_length`（`:1616-1617`） |

- `temporal = clip(1 − gap/max_gap, 0, 1)`（`:1831-1840`）；`distance = 1 − min(d, D)/D`（`:1680-1681`）；最终 `clip` 到 `[0,1]`。
- **`rule` 模式没有分数阈值**（对比 `neural` 有 `score_thresh`）：分数只决定贪心**顺序**，能不能连由硬剪 + 否决决定（`:723-737`、`:748`）。

## §7 匹配与合并层

### 7.1 贪心（最终方案）

`_greedy_match()` `:1345`，单射约束 `chosen_src` / `chosen_dst`（`:1352-1354`）。baseline 排序键（`:1392`）：

```python
(-rule_score, gap, distance, src_id, dst_id)
```

先比分数 → gap 小 → 距离近 → id 兜底（**确定性，同输入必同输出**）。变体分支追加形状/长度/`size_tiebreak` 项（`:1357-1365`），其中 `size_tiebreak` 仅在 `variant != 'baseline'` 生效（`:1360-1364`）——**最终配置下惰性**。

### 7.2 合并

`merge_tracks()` `:2293-2312`：按 `link_map` 分组到根 id → 组内按 `(start_frame, end_frame, tid)` 升序（`:2302`）→ 逐帧 `frame_to_box.setdefault(frame, box)`（`:2307`），**同帧冲突先写入者胜**。第 3 步必要：即便候选层已禁同帧共存（`:1134`），链式合并后仍可能同帧重合，`setdefault` 给出确定取舍。

## §11 陷阱清单

1. **窗口参数名**：脚本以 `--max_gap_values` / `--dist_thresh_values`（`nargs='+'`）接收窗口，默认扫描区间 `40~100` / `150~400`（`:2082-2083`）。不显式钉窗口时，脚本按 **train-argmax** 选组合，会落到 `(250,300)`（train 64.964 / test 64.139）而非论文的 `(250,450)`。
2. **边际 Δ ≠ COMB 差值**：§12 的逐层边际是**逐序列配对均值**（A1→T2 train `+1.2305`），而两个 COMB 值之差是 `64.872 − 63.745 = +1.127`，两者不等价，引用时勿混。
3. **`size_tiebreak` 在 baseline 下不生效**（`:1360-1364`），调它等于没调。
4. **`--use_best_config` 是旧配置**：`BEST_TUNED_CONFIG`（`:169+`）仍是上一代 `adaptive_tri` + `max_gap 100` / `dist_thresh 200`，会在 MCVC 上把窗口覆写掉。
5. **`kit_veto` 依赖 `--kit_labels`**：缺标签表时不报错、静默降级为「无否决」，结果会退回 A1。
6. **`--kit_veto all`** 是破坏性自检（`:813`）：HOTA 必须崩，否则说明钩子没接上。
7. **`_exp_residual_gate.py`** 仍保留旧目录名 `AFLinkMax-optimal` 的历史路径常量（未修正），仅供查阅。
8. **`fussball/aflink.py` 不是改进版**：那是原版神经 AFLink（`AFLinkNetV3` + `AFLink`），最终方案不依赖它。
